Can I run Ollama models from an external SSD?

The short answer

  1. Yes, three ways: the Ollama app's own Model location setting, the OLLAMA_MODELS environment variable, or a link at ~/.ollama/models.
  2. The catch is the unplug. In the app's source (version 0.35.1, published 29 September 2026), a models path that cannot be read is logged and replaced by the default folder, so the models look gone and the next pull fills the Mac's disk.
  3. Move ~/.ollama/models, never ~/.ollama itself: the folder above it holds keys, history and logs.

Where the models live

By default in ~/.ollama/models: blobs (the model files) and manifests, as Ollama's FAQ describes. Sizes run from a few GB to hundreds, depending on what you pulled. The folder one level up, ~/.ollama, also holds your keys, history and logs, so it is not the folder to move.

The app's own setting

The Ollama desktop app has a field labelled "Model location" in its Settings, described as the location where models are stored. Point it at a folder on the drive and copy your existing models there yourself. The value is kept in the app's own database, so Outboard never writes it: for this route Outboard would only be a guided card.

The environment variable

OLLAMA_MODELS is documented in Ollama's FAQ and is read by the server. For the Mac app, the FAQ says to set environment variables with launchctl setenv and restart the app. A value set that way is not kept across a restart of the Mac unless something sets it again; that part comes from a community guide, not from Ollama. Outboard never edits your shell or login files. Where a tool needs the variable, it shows the line as text for you to copy:

{{ollamaEnv}}

The link

The third way is to replace ~/.ollama/models with a link to a copy on the drive. It is a community method, not an Ollama setting. It is the one Outboard automates, and it marks the models "Large to download again" because that is what losing them means.

What happens when the drive is away

Ollama's app fails open. In its source at version 0.35.1, when the app starts its server it passes on the configured models path only if that path can be read; otherwise it logs "models path not accessible, using default" and starts with the default store. With the drive missing you get an empty store on the Mac's own disk, the models seem to have vanished, and a pull downloads them there.

That statement is about the app's configured path. For the link method, Outboard puts a read-only note where the folder was while the drive is away, meant to make Ollama report an error instead of starting an empty models folder. Whether Ollama does that when it finds a note in the path has not been tried on a real Mac. Not yet tried on a real Mac.

Quit first

Quit the Ollama app, including its menu bar item, and stop any ollama command. The app may start itself again, so check before you move anything.

Hugging Face, llama.cpp and LM Studio, briefly

  • Hugging Face: move the hub cache with HF_HUB_CACHE (and HF_XET_CACHE), not HF_HOME, which also holds your access token. The hub cache is built from relative links between snapshots and blobs, so a copy that follows links duplicates every blob; Outboard's copy keeps links as links and compares where they point.
  • llama.cpp: its cache is LLAMA_CACHE if set, then the Hugging Face variables, then ~/Library/Caches/llama.cpp.
  • LM Studio: it has a models directory setting of its own; Outboard shows the steps and moves nothing.
