What happens if I unplug an external drive that holds app data?

The short answer

  1. Every way of putting app data on a drive fails open when the drive is missing: the app does its first-launch thing on the Mac's own disk, with an empty library, an empty model store or a default folder.
  2. Drives go missing more often than people expect, including by themselves, and no app can make that harmless.
  3. Eject in Finder before you unplug, plug straight in rather than through a hub, and keep a backup of anything you cannot replace.

What apps do

  • Photos: Apple's page on moving a library describes Photos creating a new empty library when the one it was using is not available.
  • Ollama: in the app's source, a models path that cannot be read is replaced by the default folder, so you get an empty store. See G2.
  • Docker Desktop: its own disk image setting has a long record of problems on external drives, including failing at login because the volume was not mounted yet (docker/for-mac issue 7437). Outboard does not move its data.
  • A link that points at nothing fails closed for apps that try to open or create files under it, but not for apps that remove a folder and make a new one: those replace the link with a real folder and quietly fill the Mac's disk. This is reasoning from how links work, not a result for each app.

How drives go missing

  • Sleep. Many people report external drives ejecting during sleep and "Disk Not Ejected Properly" on wake, across macOS versions (Apple Community thread 254322044). That is forum evidence. Apple's note 101847 is about internal SATA drives in the Mac Pro (2023) and is not evidence about external drives.
  • Not mounted yet. At login the drive may not be mounted when an app starts. An encrypted drive stays locked until it is unlocked.
  • On purpose. A laptop that leaves the desk. That is normal use, and it is why a drive-away state has to be quiet and recoverable.
  • Renamed, reformatted or replaced. If a stale /Volumes/Name folder exists, a second drive with the same name mounts as "Name 1" (user reports). A link that goes by name then points at the wrong drive.
  • The drive dies. Time Machine skips external drives by default (Macworld), so the data may have no second copy.

What Outboard does while it runs

  • Unplugged or ejected. After a 5-second pause in case the drive comes straight back, the link is moved into Outboard's own folder and a read-only note is put where the folder was. For Xcode build data the setting is written back instead, once Xcode is closed. The note reads:

NoteOutboard moved this folder's contents to the drive "Outboard". The drive isn't connected, so this note is here instead. Outboard puts things back when the drive returns, but only while Outboard is running, so open Outboard if it is closed. This note does not check the data on the drive.

  • Back after a clean eject. Outboard checks the drive's identity (its UUID and a sentinel file), runs a quick check against the list it made when it copied, hashes a sample of 200 files, and then puts the link back.
  • Back after a removal without ejecting. It asks you to press "Check and reconnect", which compares every file that has not changed since it was copied. Files that changed since are listed, not compared, because the app may have written to them.
  • Something new in the way. If an app made a new folder where the note or link was, Outboard touches nothing and asks you to choose.

Guard is on while Outboard is running. It watches your drives and keeps a notice in the menu bar.

What it cannot do

  • The time between the unplug and the note is 5 seconds or more while Outboard runs, and open-ended when it isn't. If you quit, nothing watches your drives. If a drive is unplugged, apps that use it will see a missing folder until Outboard runs again.
  • It cannot veto an eject, and it cannot stop you pulling a cable.
  • Apps that kept a file open on the drive probably need a restart after it returns, because a returning drive is a new mount. This is by reasoning, not from a source we fetched, and not tried on a real Mac.
  • macOS can block an app's access to a removable volume (the "Removable Volumes" privacy category). Outboard shows that as "macOS blocked access to the drive", never as "drive missing".

What to do

  • Eject in Finder before you unplug. A pull works as far as the note goes, but it is the case that needs the full check on return.
  • Use a direct cable rather than a hub where you can, and look at your display-off sleep setting: the one that keeps disks from sleeping when the display is off is the setting people most often report helping. Outboard doesn't change your power settings.
  • If the drive holds anything you cannot replace, add it to Time Machine or keep another copy. An encrypted APFS volume is the format Outboard prefers for backups.
  • If a move went wrong, tell us; the activity log in the app lists every step with the time it happened.

Not yet tried on a real Mac: nothing on this page about Outboard's own behaviour has been run on one.
