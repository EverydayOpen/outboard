# Outboard v1 build plan (the contract)

Outboard is a free, open-source, offline macOS app (EverydayOpen's fifth, after Whydunit, Tirekick, Overstay and Aftertaste). It
is a **Storage Planner** for people with an external SSD: it measures the big folders that apps keep on the Mac, says which ones
can be moved and how, moves the ones with a known method (a verified copy, the original kept, every step logged), guides the
rest, and runs a **Drive Guard** that announces a missing drive and parks a note where the folder was. It does not auto-configure
new installs (there is no install hook) and it does not make an external drive behave like internal storage.

The product decision, evidence, launch plan and kill tests are in the Whydunit repo's `docs/next/APP6.md`, `IDEA3.md` and
`app6-research-{recipes,guard-tech,safety-ux,competitors-names}.md` (quoted below only where code depends on them). This file is
the build contract for parallel owners (§10). Where it disagrees with APP6, this file wins (§13 lists every disagreement and every
architect ruling); propose changes in your report instead of diverging.

**What has run:** `OutboardCore/Model` (the frozen types) and one test suite for them build and pass on Linux in Docker
(`bash tools/test_core_docker.sh`, 2026-10-03, no warnings). `tools/safety_greps.sh` passes on that tree, including every
mutation self-test (about 13 minutes on Windows Git Bash; `SAFETY_FAST=1` skips the mutation runs, about 35 s). Nothing else
exists yet. There is no Xcode on the dev machine, so every Mac and App file is "written, not compiled" until a `macos-26` CI run
says otherwise, and **nothing about runtime behaviour on a real Mac is claimed** (AGENTS.md): every such claim is VERIFY (§12).

## 2. The product in one page

**Three honest claims**, each tied to a check (APP6 §0, safety-ux §10.1): the copy is compared file by file (size and SHA-256)
before anything on the Mac changes; the original is kept, renamed, until the user confirms; every step is in a log the user can
read. Plus a Drive Guard that, *while the app runs*, announces a missing drive and parks a note where the folder was.

**Verbs.** Measure (read-only). Move (copy, verify, switch). Confirm and move to Trash. Roll back (before confirming). Return to
Mac. Forget (drive gone for good). Park and unpark (the guard). Check and reconnect (after an unclean removal). Guided cards move
nothing. **No permanent deletion of any kind**: the original is renamed, and only after confirmation `FileManager.trashItem`.

**Catalogue (APP6 §4.2).** 7 automated recipes, 8 guided cards, 9 never cards. Ids (frozen; journaled):

| Kind | Ids |
|---|---|
| Automated (7) | `xcode-deriveddata` (defaults, B1), `huggingface-hub-cache`, `ollama-models`, `llamacpp-cache`, `npm-cache` (symlink, B2), `ios-device-backups` (symlink, B3, FDA, sensitive), `xcode-archives` (defaults, B4) |
| Guided (8) | `mas-large-apps`, `photos-library`, `music-media-folder`, `final-cut-library`, `logic-sound-library`, `steam-library`, `lmstudio-models`, `android-sdk` |
| Never (9) | `never-containers`, `never-apple-data` (Mail, Safari, Messages, Notes), `never-homebrew`, `never-caches-home`, `never-icloud`, `never-app-bundles`, `never-simulator-runtimes`, `never-docker-orbstack`, `never-pnpm-uv` |

**Rollout by consequence (APP6 §4.1).** B0 (measure, explain, guide; every automated recipe `verifiedOnRealMac: false`, hidden
unless "Show moves not yet tried on a real Mac" is on), B1 `xcode-deriveddata`, B2 the symlink caches, B3 iOS backups, B4 Xcode
Archives. A step ships only after the previous one has a `docs/VERIFY_LOG.md` entry from a named tester on a real Mac. The release
build hides an unverified recipe's mover unless the preference is on (`Catalogue.visibility`), and the consent sheet then carries
"Not yet tried on a real Mac." as a **flag-driven line, never baked into the recipe's own text**.

**Honest copy.** `tools/banned_phrases.txt` is enforced by CI (G15). The fixed report footer, verbatim: "This report lists what
Outboard did and checked. It does not show that your data is undamaged or that a drive is reliable. Outboard has not been tried on
every Mac or every drive." The word "safe" appears nowhere ("safety copy" passes the pattern).

## 3. Safety rules (review + CI; all hard)

The product renames, copies and links other apps' data and then points the apps at it. A wrong deletion, an overwritten folder or
a link that points at nothing is the failure that kills the product. Invariants I1 to I14 (APP6 §4.10, safety-ux §1) are rules,
not guidelines:

1. **I1 Two copies or consent.** From the end of Verifying until OriginalTrashed a hash-verified copy exists on the drive and the
   original exists on the Mac (renamed once swapped). The Core recovery simulator asserts it after every crash point.
2. **I2 Nothing is deleted.** Rename, then `trashItem` after confirmation. No `removeItem`, `unlink`, `rmdir`, `rm`, `replaceItem`,
   `truncate`, `ftruncate`, `renamex_np`, `copyfile`, `clonefile`, `ditto`, `rsync` anywhere in `Sources/` or `App/` (G1).
3. **I3 Journal before act, fail closed.** Each verb's file appends its own `intent` line (`fsync`ed) and refuses to act if that
   fails; a `result` line follows. If the journal is unwritable nothing moves (G13, G17).
4. **I4 Fail closed on unknowns.** Unknown volume type, running state, stamp, Time Machine status (irreplaceable), journal error:
   refuse and name the signal. `Tri.unknown` never becomes "yes" (§4.3 unknown-signal table).
5. **I5 One mutation in flight; one instance.** `LSMultipleInstancesProhibited` (VERIFY it blocks a copy from another path).
6. **I6 The target app is not running**, checked fresh with no suspension point between the check and the act (before W2, and before
   every park, unpark, rollback and trash). The app never quits, signals or kills anything (G6).
7. **I7 Identity is UUID + sentinel + root stamp**, never the name or the path. No `createDirectory` under `/Volumes` without a
   UUID-mounted check (`VolumeIdentity.mounted(` before `createDirectory(`, pinned). A stale `/Volumes/<Name>` makes the real drive
   mount as `<Name> 1`: health compares the *resolved target's* volume UUID.
8. **I8 Nothing in iCloud:** not the source, the destination, staging or the journal (E13, P4, `NeverList`, G11).
9. **I9 File contents are read only to hash them** (`Verifier`) and for our own journal, manifests, marker and sentinel (G7). No network (G10).
10. **I10 One model.** Every state and count shown comes from `RelocationRecord` (folded from the journal by `RelocationFold`) plus a
    *derived* `Health`. The Activity screen, the export and crash recovery render the same `JournalEntry` lines through `ActivityText`.
11. **I11 Read-only system.** No eject, mount, unmount, power, Time Machine, iCloud or FileVault change; `diskutil` and `tmutil` are
    read-only; `defaults write` only catalogue keys; no `launchctl`; no `hdiutil` in the app (G4, G5, G6).
12. **I12 Honest wording.** Public text claims only what a check performs (G15). No speed claim, no "safe to unplug", no "intact".
13. **I13 Recipes are data**, validated, bundled, never fetched; a Mac file cannot invent a restore verb (G20).
14. **I14 No personal paths, no AI credits, EverydayOpen identity** (§3.3).

Further rules the greps encode: the guard's twelve states fail closed (`NeedsPermission` never parks; `Suspect` never restores;
`Diverged` and `Foreign` are never touched or merged); a foreign folder is renamed aside (`.created-while-moving`,
`.created-while-rolling-back`, `.while-away-<date>`), never merged or deleted; a timed-out command is abandoned, never signalled;
`F_FULLFSYNC` is banned (the filesystem is the source of truth; a torn last journal line is ignored); materialization of dataless
files is off for the whole process from the first statement of the app (`EDEADLK` means dataless: record it, do not retry).

### 5.5 The move (what the engine does, in order)

Preflight P1 to P14 (`Preflight.run`) -> staging `<root>/<recipe>/.staging-<id>` with a marker -> `Copier.copy` (progress by bytes polled
every 500 ms; `ProcessInfo.beginActivity(.idleSystemSleepDisabled)`; `willSleep` during a copy journals `interrupted-by-sleep`) ->
`Verifier.verify` (V1 `lstat` walk both trees; V2 SHA-256 of every file both sides, destination read with `F_NOCACHE`; V3 re-walk the
source against the manifest taken at copy start) -> `Renamer.perform(.publish)` + sentinel + manifest -> W1 `Guard.recheck` +
`RunningCheck.state` (**no suspension point to W3**) -> W2 `Renamer.perform(.setAside)` -> W3 `Redirect.apply` (`EEXIST` = a foreign
folder appeared: set aside as `.created-while-moving`, roll back, never merge) -> W4 `Health.check` -> `Journal.result(.swapped`.
Rollback (Swapped only), Return to Mac, Forget, Confirm/Trash and the recovery table are as APP6 §4.4. Any mismatch aborts with the
first 20 differences and nothing on the Mac changed.

### 5.6 Special cases and honest limits (said in the app)

`copyItem` is a real copy across volumes, not an APFS clone; hard-link groups are not preserved by `copyfile` recursion (the verifier
compares by path and content, counts hard-linked files once in the free-space sum, reports "N hard-linked files were copied as
separate files"); sparse sources are refused in v1; cancelling a running `copyItem` is VERIFY (the `FileManager` delegate
`shouldCopyItemAt` returning false is the candidate). The window between unplug and park cannot be zero and is unbounded while the app
is not running; the app cannot veto an eject. Open file handles in other apps do not heal when the drive returns ("restart <App>"
after unpark). After a relocation Time Machine will not back up the drive unless the user adds it.

### 5.7 `LoginItem`, `VolumeWatcher`, `RunningApps`

`SMAppService.mainApp` only; `register()` only after the user says yes on the first move; after every update the app re-reads the
status. `VolumeWatcher` observes `NSWorkspace.shared.notificationCenter` for mount, unmount, will-unmount (advisory), rename (if it
exists, VERIFY), will-sleep and did-wake; wake waits 15 s, launch waits 20 s for volumes not yet seen this session; a 10 s timer runs
while any relocation exists. `RunningApps.snapshot` builds a `RunningSnapshot` from `NSRunningApplication`, `Processes` names and, if it
lands, `Processes.openHandleHolders` (Should; if not, layers 1 and 2 and the manual checkbox ship and the sheet says so).

## 13. Where this plan differs from APP6.md and the task brief (resolved here)

1. **Mac file names follow APP6 §4.11 / safety-ux §11, not the brief's shorthand.** The brief's *Mover, Parker, DefaultsWriter, JournalStore, GuardWatcher, VolumeScanner/DriveInspector, SizeScanner* map to the files in §1 "Task shorthand". One site per verb is the rule that makes the greps meaningful; a single `Mover` file with `moveItem` and `copyItem` would break G2.
2. **Pins use `Linker.create(`, not `Linker.link(`**: a function named `link` is flagged by G1 (a declaration is not preceded by a dot). Same reason `RedirectPlan` has `symbolicLink(...)` and `RecipeMethod` keeps a no-argument `symlink`.
3. **`posixPermissions` is also allowed in `Park.swift`** (APP6 G3 listed Journal, ManifestStore, Placeholder): `Parked/<moveID>/` is created 0700 there, and `Rollback` parks through `Park`. `createDirectory` family is allowed in `Copier` (staging) and `Park` (Parked), as APP6 G3 lists.
4. **AppKit is allowed in `VolumeWatcher.swift` as well as `RunningApps.swift`** (APP6 G12 listed only the latter): `NSWorkspace.notificationCenter` needs `import AppKit`. The `NSWorkspace` token rule (G9) allows both files for the same reason.
5. **`Policy.init` is internal** instead of grepping the stored property name: `allowDiskImages` would otherwise appear outside `#if DEBUG` in the shipping type. G14 scans `Faults.` and `Policy.testing`; G16 scans `Policy(`.
6. **The "Not yet tried on a real Mac." marker rule counts `Recipe(id:` entries against `verifiedOnRealMac: true`** because recipes are Swift data (APP6 §4.2 / G15 assumed JSON files). `tools/check_recipes.py` reads the exported golden JSON.
7. **`JournalEntry.step` is a String** (not `MoveStep`) so an unknown step is shown raw, as APP6 §4.9 requires; `moveStep` gives the typed value when known.
8. **`ActivityEntry` is the rendered row, `JournalEntry` is the file line.** The brief listed both; I10 requires one record store, so the entry type is the journal line and `ActivityText` renders it.
9. **Unknown-signal table** (§4.3): APP6 gave the general rule (refuse for irreplaceable, ack otherwise); the table fixes it per rule, with E3, E6 and E12 refusing in both cases and E15 informational.
10. **Rules take a `RuleContext`** (§4.4) built from the plan or the record, so `RenameRules`, `CopyRules`, `LinkRules` and `TrashRules` have one shape and the Mac layer cannot pass free paths.
11. **`Backend` closures** are the APP6 §4.13 list plus what the screens need (`blockers`, `fullDiskAccess`, `useDrive`, `relocations`, `leftovers`, `setAsideAndReconnect`, `checkAndReconnect`, `trashLeftover`, `recordGuideViewed`, `watch`, `setLoginItem`). `eligibility` re-reads the drive (E18); it is not a pure function of cached facts.
12. **Recipe ids are frozen in §2** because they are journaled; the never cards are `Recipe`s with `.never` (one catalogue, one list).
13. **Education text is in this file (§8.1) with `Storage Planner`/`Overflow` replaced by `Outboard`/`your Outboard drive`**; consent texts are taken from safety-ux §5 with the same replacement and the unverified line removed from the text.
14. **Closed by the Docker run:** `Model` compiles in Swift 5 mode on Linux with no warnings, `Policy.testing` is behind `#if DEBUG`, and `OutboardMac` is declared only on macOS.
